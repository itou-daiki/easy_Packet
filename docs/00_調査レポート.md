- 調査日: 2026-09-18
- 対象: https://github.com/itou-daiki/easy_Packet @ `31182e0`
- 公開先: https://itou-daiki.github.io/easy_Packet/ （HTTP 200・稼働中）
- 調査方法: `python3 -m http.server` でローカル配信し、実ブラウザ上で計測・DOM/Canvas 検査・外部通信遮断シミュレーションを実施

## F-1 【最優先・致命】canvas サイズの無限増殖

### 実測値

`resize` イベントを1回ずつ発火させたときの canvas 幅：

| resize 回数 | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| `canvas.width`(px) | 1600 | 3200 | 6400 | 12800 | **25600** |
| CSS 実幅(px) | 1600 | 3200 | 6400 | 12800 | **25600** |

**1回ごとにちょうど2倍**。4回で16倍になります。

### 原因

`visualizer.js:15-35` `setupCanvas()`

```js
this.canvas.style.width = '';            // ① CSS幅のピン留めを外す
this.width = rect.width;                 // ② 要素の実測幅を読む
this.canvas.width = this.width * dpr;    // ③ 属性widthに 実測幅×2 を代入
```

canvas の `width` **属性**は要素の固有サイズ（intrinsic size）そのものです。①で CSS 幅の固定を外しているため、③で属性を書き換えると要素の表示幅もそのまま変わり、次回の②はその倍増した値を読みます。**測定 → 拡大 → 再測定の正のフィードバックループ**です。

`expandCanvas()`（`visualizer.js:172-180`）も同じ `style.width` を書き換えるため、`setupCanvas()` と互いに上書きし合います。

### 影響

- **図形が歪む**: 実測で backing store が 1600×487、CSS ボックスが 1600×244。横 1.00 px/CSS px、縦 2.00 px/CSS px。`ctx.scale(dpr,dpr)` は等方なので、**描画全体が横に2倍伸びる**。ノードの円が楕円になります。
- **レイアウトが横に破綻**: 375px 幅の端末で、`.commands-area` / `.tutorial-area` の幅が **1620px** に膨張。
- **操作不能**: `style.css:12` の `body { overflow: hidden }` により横スクロールできず、膨張して画面外に出た**コンソール入力欄とクイックコマンドボタンに到達できません**。
- **メモリ肥大**: 25600×487×4byte ≈ 50MB。増殖が続けばタブがクラッシュします（推定）。

### 発火条件

ウィンドウリサイズ、画面回転、ソフトキーボードの表示/非表示、ブラウザのズーム操作。**授業中に普通に起きる操作**です。

## F-2 【最優先・致命】仕様と正反対の外部 API 依存

### 仕様書（`CLAUDE.md`）の記述

> サーバー側のプログラム（バックエンド）を持たず、HTML, CSS, JavaScriptのみで構成される**完全な静的サイト**として構築します。
> **実際のネットワークにパケットを送信することはありません。**
> 演習に必要なドメイン名、IPアドレス、経路情報などは、…**JSONファイル（dns.json, routes.json）としてアプリ内に保持**します。
> **安全性**: 実際のネットワークを使用しないため、どのような環境でも安全に利用できます。
> **安定性**: 外部環境に依存せず、**いつでも同じ結果を再現**できるため、授業計画が立てやすくなります。

### 実装の実態

`simulator.js` は外部 API を呼んでいます。

| 行 | 呼び先 | 用途 |
|---|---|---|
| 31, 63, 106, 171 | `https://dns.google/resolve` | nslookup / ping / traceroute の名前解決 |
| 181 | `https://ipapi.co/{ip}/json/` | traceroute の経路推定 |
| 311 | `https://api.ipify.org` | ipconfig のグローバルIP取得 |

`dns.json` / `routes.json` は `loadData()` で読み込まれているにもかかわらず、**nslookup と ping では一度も参照されません**。

### 実測：外部通信を遮断すると全滅

学校のフィルタリングを模して外部 fetch を遮断した結果：

```
$ nslookup google.com   → error: *** DNS問い合わせに失敗しました: Failed to fetch
$ ping google.com       → error: ping: google.com: DNS解決に失敗しました
$ traceroute google.com → error: traceroute: エラーが発生しました: Failed to fetch
$ ipconfig              → error: グローバルIPアドレスの取得に失敗しました
```

**4コマンドすべてがエラー**。`dns.json` にデータがあるのに使われません。

### フォールバックがデッドコード

`simulator.js:136-158` に「APIが使えない場合はシミュレーション」のフォールバックがありますが、**到達不能**です。`106行目`の fetch が reject すると `161行目`の外側 catch に飛ぶため、フォールバック節は素通りされます。

### ipapi.co のレート制限

- 無料枠は **1,000リクエスト/日・IP単位**。
- 教室は NAT で**全員が同一のグローバルIP**を共有するため、1クラスで枯渇します。
- 本調査でも curl から **HTTP 429 Too Many Requests** を実際に受領しました。

## F-4 【高】実行後 6.3 秒間、画面が無反応

`traceroute google.com` で Enter を押してから、コンソールに最初の1行が出るまでの実測：

| イベント | 経過時間 |
|---|---|
| 最初の1行が出る | **6,348 ms** |
| 以降10行が出力 | 6,348 → 8,484 ms（約200ms間隔） |
| アニメーション開始 | **約 8,500 ms** |

**6.3秒間、ローディング表示もなく完全に無反応**です。生徒は固まったと判断します。`ping` も 300+800×4 = 約3.5秒無反応。

### 原因

三段階に分かれて時間がずれています。

1. `simulator.execute()` が **内部の sleep をすべて消化してから**結果配列をまとめて返す（`simulator.js:125-134` 等）
2. `app.js:98-121` がその配列を改めて 200ms 間隔で「再生」する
3. `app.js:124-139` で**出力が全部終わってから**アニメーションを開始する

つまり「1行ずつ表示」は実際の処理と連動しておらず、**録画の再生**になっています。仕様書が求める「コンソールの表示と連動して、パケットが各ルーターをリレー形式で経由していく」が成立していません。

# 追加調査（第2次）

初回の4件に加えて、実機検証で以下を確認しました。

## F-13 【致命】描画で例外が起きるとコンソールが永久ロックする

### 実測

`visualizer.executeAnimation()` が例外を投げる状況を作って `nslookup google.com` を実行：

```
例外              : "描画エラー"（executeCommand の外まで漏れる）
例外後のisExecuting: true    ← 戻らない
結果              : Enter もクイックコマンドボタンも以降まったく効かない
```

### 原因

`app.js:76-143` の `executeCommand()` に **try/finally がありません**。

```js
this.isExecuting = true;
...
this.visualizer.executeAnimation({...});   // ここで例外が出ると
this.isExecuting = false;                  // この行に到達しない
```

### 影響

授業中に一度でも描画エラーが起きると、その生徒の画面は**リロードするまで完全に操作不能**になります。エラー表示も出ないため、生徒は「壊れた」としか分かりません。

---

## F-14 【高】失敗したコマンドでも成功アニメーションが再生される

### 実測

`ping www.google.com`（F-5 により必ず拒否される入力）を実行：

```
コンソール: 「❌ URL形式では実行できません」「コマンドを修正して再度実行してください。」
図        : パケットが1個、正常に飛んでいる（packets.length = 1）
```

### 原因

`app.js:124-139` はコマンド名だけを見てアニメーションを起動しており、**実行が成功したかどうかを一切見ていません**。

```js
} else if (cmd === 'ping') {          // 結果の成否は未チェック
    this.visualizer.executeAnimation({ type: 'ping', route: routeData });
}
```

### 影響

引数なしの `ping`、存在しないドメイン、拒否された入力 ── いずれの場合も図の上では**通信が成功したように見えます**。「コンソールの文字」と「図の動き」が食い違う教材は、理解を助けるどころか妨げます。

---

## F-15 【高】アイドル時も canvas を描き続ける

`visualizer.js:288-322` の `animate()` は、パケットが0個でも**無条件に `requestAnimationFrame` を再登録**し、毎フレーム `drawStaticNetwork()` を呼びます。さらにその中の `generateNodes()`（`visualizer.js:78-170`）が**毎フレーム新しいノード配列を生成**します。

何も操作していなくても CPU と GPU を使い続けるため、Chromebook やタブレットではバッテリーを消費し、発熱します。F-1 の canvas 肥大と重なると負荷が跳ね上がります。

## F-17 【中】操作フィードバックの欠落

実測で確認した挙動：

| 挙動 | 実測 | 問題 |
|---|---|---|
| 起動時に入力欄へフォーカス | **入らない** | 生徒はまずクリックが必要 |
| 実行中にコマンドボタンを押す | 実行はされないが**入力欄だけ書き換わる** | 入力中の文字が黙って消える（`app.js:41`） |

## F-18 【中】未使用の外部CDNが3本、SRI もなし

`index.html:7,8,176`

```html
<link rel="stylesheet" href="https://cdnjs.cloudflare.com/.../codemirror.min.css">
<link rel="stylesheet" href="https://cdnjs.cloudflare.com/.../theme/monokai.min.css">
<script src="https://cdnjs.cloudflare.com/.../codemirror.min.js"></script>
```

- 実際の入力欄は素の `<textarea>`（`index.html:94`）で、**CodeMirror は一行も使われていません**
- `integrity` 属性は **0個**（SRI なし）。CDN が改ざんされた場合、任意のスクリプトが実行されます
- Content-Security-Policy の指定もなし
- CDN が学内フィルタで塞がれると、無駄な読み込み待ちが発生します

使っていないのですから、**消すのが唯一の正解**です。
