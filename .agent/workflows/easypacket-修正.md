# easyPacket 修正ワークフロー

## 0. 最初にやること

次の3つを**全文**読んでから作業を始める。読まずに着手しない。

1. `docs/00_調査レポート.md` — 実装の不具合 F-1〜F-20。すべて実機で計測した実測値つき
2. `docs/02_内容点検.md` — 教材内容の誤り C-1〜C-9。`dig` と `whois` で裏取り済み
3. `docs/01_実装計画_Antigravity.md` — Phase 0〜9 のタスクと検証条件

## 1. 状況の要約

このアプリは「動かない」と報告されている。原因は単一ではなく、**独立した3つの致命傷**。

- **F-1** `visualizer.js:15-35` が canvas 自身の実測幅から `canvas.width` を決めているため、
  resize のたびにサイズが倍増する（実測 1600 → 3200 → 6400 → 12800 → 25600px）。
  図が横2倍に歪み、レイアウトが破綻し、`body{overflow:hidden}` と相まって
  入力欄とボタンに到達できなくなる。
- **F-2** 仕様書は「完全な静的サイト・外部に送信しない」と書いているのに、実装は
  `dns.google` / `ipapi.co` / `api.ipify.org` を呼ぶ。外部通信を遮断すると4コマンド全滅。
  `dns.json` は読み込まれているが**読み出しが1箇所もない死にデータ**。
- **F-13** `app.js:76-143` に try/finally がなく、描画で例外が出ると `isExecuting` が
  true のまま残り、コンソールが永久ロックする。

## 2. 実行手順

### 各フェーズで必ず踏む4ステップ

1. **概要提示** — そのフェーズで変更するファイルと方針を箇条書きで出し、**承認を待つ**
2. **実装** — 承認後に着手。1フェーズ＝1コミット
3. **検証** — `docs/01_実装計画_Antigravity.md` の該当フェーズのチェック項目を
   **実測値で**埋める。推測で「直ったはず」と書かない
4. **報告** — 修正前後のスクリーンショットと、検証コマンドの出力を添えて報告する

### 着手順

```
Phase 0 ──► Phase 1 ──┬──► Phase 2 ──► Phase 4 ──┐
 (テスト基盤)  (canvas)  ├──► Phase 3 ──────────────┤
                       └──► Phase 5 ──────────────┼──► Phase 9
                            Phase 6 ──────────────┤   (仕上げ)
                            Phase 7 ──────────────┤
                            Phase 8 ──────────────┘
```

**Phase 1 は必ず単独で先に完了させる。** 他のフェーズは canvas サイズが安定していることを
前提にしている。ここを飛ばすと全部やり直しになる。

### 承認が要る判断

**Phase 3 のデータソース方針は、着手前に必ず確認を取ること。**

- 案A（推奨）: 完全オフライン — `dns.json` / `routes.json` のみ。外部通信ゼロ
- 案B: オフライン既定＋ライブ任意 — トグルか `--live` で実DNSも引ける。失敗時は自動でオフラインへ
- 案C: ライブ優先のまま、エラー処理とフォールバックだけ確実にする

他のフェーズはこの選択に依存しないので、確認待ちの間も Phase 1 / 2 / 5〜8 は進めてよい。

## 3. 完了の定義

全部満たしたら完了。

- [ ] 外部通信を全遮断した状態で4コマンドすべてが動く（現状は4つとも即エラー）
- [ ] `file://` で開いても動く
- [ ] `resize` を20回発火させても `canvas.width` が変わらない（現状は16倍になる）
- [ ] 375px〜1920px のどの幅でも図が歪まず、目的地ノードが画面内に収まる
- [ ] Enter から最初の出力まで 300ms 以内（現状 6,348ms）
- [ ] 失敗したコマンドで成功アニメーションが流れない
- [ ] 描画で例外が出てもコンソールがロックされない
- [ ] コントラスト比が全箇所 WCAG AA を満たし、キーボードだけで完走できる
- [ ] 全ダミーIPが RFC 予約領域内（機械的に検査するテストを置く）
- [ ] `dns.json` の `google.com → 8.8.8.8` が直っている（8.8.8.8 の逆引きは `dns.google`）
- [ ] `node --test` と CI が緑
- [ ] README がある

## 4. やらないこと

- フレームワーク（React/Vue 等）への移行
- ビルドツール（Vite/webpack 等）の導入
- 実際に ICMP を送る機能（ブラウザでは不可能であり教育上も不要）
- 新しいコマンドの追加（まず既存4つを確実に動かす）
- デザインの全面刷新（配色・レイアウトの骨格は維持）
